## Data model
- `classes.term` holds `START..END` (ISO dates); it defines the scheduled class days and `remaining_sessions`.
- `classes.weekday_mask`: Mon=1, Tue=2, Wed=4, Thu=8, Fri=16, Sat=32, Sun=64; `--days 화,금` or `tue,fri`.
- A class day = a `sessions` row OR a scheduled weekday inside the term (so the Friday pilot needs no `session start`).
- `submissions` has no set column (exact schema): the set id is kept in the Worker record and the `submission` event payload.
- One submission row per student per day (`UNIQUE(student_id, day)`); a phone upload after a teacher/paper mark turns it into `phone`.
- One attitude row per student per session; a second tap corrects it (the `events` log keeps every tap).
- `said_aloud` = 1 for board taps, 0 for `daybook score`.
- `events` is append-only, enforced by SQLite triggers; the last pull position is the latest `pull` event (no extra table).
- Extra indexes and a `PRAGMA user_version` = 1 for future migrations.
- Slug = the display name, de-duplicated with a numeric suffix; editable with `roster edit --slug`.
- Times are stored as UTC ISO; "day" is computed with a fixed UTC+9 (Korea has no DST), no tz database needed.

## Derived values
- Streak: today without a submission is still open (neither counts nor breaks); a past class day without one breaks.
- The student page computes the streak for days after the publish date in the browser (Worker `/status` days + schedule), on top of the streak through the day before publish.
- Reward goal = active × remaining sessions × `goal_coef`, rounded up, computed at the first publish and frozen into `reward_goal_points` (a goal that shrank every week would never fill); `daybook class edit <c> --goal 0` recomputes.
- `class_total` = all attitude points of the class's active students over the whole term. Multiple reward cycles per term: deferred.
- "반 누적 +N" on the 오늘 완료 screen = the class total as of the last publish (the Worker never knows classes).
- Trend: least-squares slope per round over the last 6 rounds; thresholds 0.01 (efficiency) and 0.03 (reach); the SVG y-axis is 0–100 % and assumes both values are 0..1 (clamped).
- Class median band on the trend: deferred ("median band deferred").

## Importers
- Screeners: match `student` → `ext_id`, else `name` → `full_name`, else `student` → `full_name` (the field may hold a name); a name shared by two students is reported as ambiguous, never guessed.
- Unmatched rows are printed and counted in the `import_screeners` event; the import still exits 0 so the rest is kept.
- Re-imports upsert on (student, test_name, date) and (ext_id | unambiguous full_name): no duplicates, tokens kept.
- Roster rows not in the CSV are left as they are (never deleted); `Status` values other than `active_values` → inactive.
- A display name equal to the full name (2- or 4-character names) is allowed at import with a warning, and publish refuses it until `roster edit --display`.

## Publish and pages
- Publish renders into `.dist-staging/`, lints it, and swaps it into `dist/` only if clean; a failed publish leaves `dist/` and the DB unchanged.
- Lint errors: phone pattern, any `full_name`, `ext_id` (word-bounded), `parent_phone` digits, non-generic `<title>`/`og:`, third-party resources, files > 100 KB. Another student's display name on a per-student page is a warning only (short given names collide with ordinary words).
- `dist/_headers` sets `X-Robots-Tag: noindex`, `Referrer-Policy: no-referrer` and a CSP (`connect-src` = self + the Worker); `robots.txt` disallows all.
- The parent page has no JavaScript and no links; the student page loads one same-origin script.
- `videos.json` is inlined into the student page at publish (no runtime fetch); only http(s) URLs are kept; newest first per group.
- Each student page has its own `manifest.webmanifest` (`start_url ./#today`) so the home-screen icon opens that student's page; there is no shared `static/manifest.webmanifest` and no service worker (offline: deferred).
- Student JSON data is embedded as `<script type="application/json">` with `<`, `>`, `&` escaped.
- The demo uses its own `demo.sqlite` and refuses to seed a database that has non-demo students.

## Worker
- Added `GET /status?t=` (the token's days in the last 8 days) so a reopened 오늘 tab shows "done" and the streak is right between publishes.
- Records (token, day, ts, key; no photo) live 14 days (`RECORD_TTL_DAYS`), photos 7 days (`PHOTO_TTL_DAYS`): a weekly pull must not miss a 7-day-old record.
- The record is also stored as KV metadata so `/submissions` needs only `list` calls, no per-key reads.
- CORS: a browser request from another origin to `/submit` or `/status` gets 403; requests without `Origin` (curl, console) pass; teacher endpoints need `X-Teacher-Token` (constant-time compare).
- Uppercase tokens are lower-cased before validation; `set` is restricted to `[A-Za-z0-9_-]{0,80}`.
- The KV rate-limit counter is approximate (KV is eventually consistent); good enough for 10/hour.
- If the browser cannot decode the photo (e.g. HEIC on desktop Chrome), the original is sent if ≤ 8 MB.
- Pull reads since the previous Worker `now` − 5 minutes (KV list is eventually consistent); upserts are idempotent.
- Old student tokens from `roster rotate-tokens` still map to their student on pull (kept in the event log).

## Console and board
- Extra commands beyond the brief: `class add|edit|list` (roster commands need a class), `roster edit`, `roster list --links` (to send links), `submit` (paper/teacher mark), `pull --photos`.
- The board creates today's session when it starts; it is bound to 127.0.0.1 and refuses cross-origin POSTs.
- Playwright checks run in Node (`tests/e2e/check.cjs`, same runtime as the Worker tests); `make` installs Playwright only if Node cannot already resolve it.
- Config lives in `daybook.json` (gitignored) or `DAYBOOK_*` environment variables; the teacher token never enters the repo.

## F4: 오늘의 장면 (2026-11-03)
- Schema v4: `moments (id, class_id, session_id, ts, text, image_key)`, at most 3 per session; images live in `moments_dir` (default `moments/`, gitignored), never in git.
- On the laptop, before anything is stored or sent: `ImageOps.exif_transpose` then a fresh RGB copy (all EXIF/GPS/ICC dropped), long edge ≤ 1080 px, JPEG quality stepped down to ≤ 200 KB. The gate "학생 얼굴·이름·문제집 원문 전체가 보이지 않나요? (y/N)" defaults to N; only y stores (CLI prompt; a checkbox on the board that the server also requires).
- Same day: the console PUTs the JPEG (base64) to `/moment-put`, stored as `moment:<class key>:<date>:<n>` with a 14-day TTL. A student token reads only its own class (`GET /moments?t=` → metadata + counts + its own reaction; `GET /moment?t=&k=` → the JPEG, shown through a blob URL so the CSP stays `img-src 'self' blob: data:`). The page asks only after `load`.
- Saturday publish bakes the moments as 720 px ≤ 100 KB copies into `dist/m/<class key>/<date>_<n>.jpg` (the class key, never the name). The student story shows the moments of the last 7 days; the parent report shows up to 3 per week ("이번 주 수업 장면"), without reaction counts.
- Reactions 🔥 👏 🤯: anonymous class counters (`POST /react`), one per token per moment, the first tap counts; students see the totals; the board shows the latest totals ("지난 장면 반응"). No names, no comments, no ranking.
- The ritual is ① 출석 → ② 장면 → ③ 과제 끝 on class days. Step ② is done when the student opened today's moment (✓) or reacted (the emoji); without a moment today it shows "–" and never blocks. The day summary reads "출석 18:02 → 장면 🔥 → 끝 20:55". In the taste build step ② uses the newest baked moment and reactions stay in the browser.
- The board uploads a file (on a laptop that is a file or the camera app's photo); a live webcam capture is deferred.
- `/moments` for a token whose class is unknown answers an empty list (not 404), so the student console stays clean.
- Demo: two synthetic chalkboard scenes on each class's latest class day and one on the class day before (with synthetic EXIF, so the stripping runs in every demo).

## Hotfix H1–H6 after the local review of `0419974` (2026-11-03)
- H1 (choice (a)): the Worker's records moved from KV to **D1** (Cloudflare's SQLite): submissions, check-ins, sessions, the token map, moments, reactions and rate counters. KV keeps only the photos and moment JPEGs (with TTLs). No KV `list` is used anywhere; the board's poll is three indexed `SELECT … WHERE updated/ts > ?` queries.
- The Worker creates its tables itself (`CREATE TABLE IF NOT EXISTS`, once per database binding); a daily cron (04:17 KST) deletes records older than `RECORD_TTL_DAYS` and rate counters older than 2 days.
- The board polls every **60 s** (`board_poll_seconds`) and only from 30 min before the session start to 2 h after it; outside that window it does not call the Worker at all.
- Class-day budget (`worker/test/budget.test.mjs`, the real Worker code against a SQLite-backed D1 stand-in): 20 students, a 3 h board at 60 s, 3 moments × 20 reactions, 5 page opens per student, 20 check-ins, 21 uploads, one pull. Free plan per day; the test fails at 30 %.

  | resource | used | free limit | share |
  |---|---|---|---|
  | Worker requests | 910 | 100,000 | 0.9 % |
  | KV reads | 60 | 100,000 | 0.06 % |
  | KV writes | 24 | 1,000 | 2.4 % |
  | KV lists | 0 | 1,000 | 0 % |
  | D1 rows read (estimate: rows returned + 1 per query) | 10,103 | 5,000,000 | 0.2 % |
  | D1 rows written | 188 | 100,000 | 0.19 % |
- H2: a reaction is one row `(moment, token)` inserted with `INSERT OR IGNORE`; totals are `COUNT(*) … GROUP BY r`. No shared counter key, so 20 simultaneous taps all count (tested). Rate limits are atomic `INSERT … ON CONFLICT DO UPDATE SET n = n + 1 RETURNING n`. Any storage error answers `{ok: false, error: "storage"}` with 200 on student endpoints (503 on teacher endpoints), never a 500.
- H3: `/submit` accepts only tokens in the token map (`not_ready` while there is none, `unknown_token` otherwise; both 200 + ok:false, nothing written, no rate-limit row). The console sends the map (`PUT /tokmap`, replaces it) after every successful publish, after `roster add|import|rotate-tokens` and after `roster edit --active/--inactive/--class`, and with every `session start`. A send failure is a warning, never a failed publish.
- H4: the e2e copies `demo.sqlite`, the demo config and the moment store into a temp folder and works only there; its taste build goes to the temp folder; its texts read like class content. The taste lint rejects the words e2e, test(s), fixture(s), dummy in visible text (not in scripts or attributes).
- H5: all four `.ps1` scripts use `$ErrorActionPreference = 'Continue'` and test `$LASTEXITCODE` after each native command; the Playwright probe runs through `cmd /c`. Static pytest checks: ASCII only (5.1 reads BOM-less scripts as ANSI), no 'Stop', no native `2>$null`. They were not executed here (no PowerShell in the cloud build): the local agent confirms on 5.1.
- H6: the profile bio's "{n}번째 기록" is recomputed in the browser from the same value as the 제출 counter. Demo times are realistic: 출석 17:40–18:09, 과제 끝 19:50–21:00 (earlier the same day when the seed runs before then).
- Node ≥ 22 is now needed for the local Worker tests and the dev server (`node:sqlite`); they run with `--experimental-sqlite --no-warnings` so Node 22.5–22.12 works too. The deployed Worker is unaffected.

## F8: answer-card reading spike (2026-11-03)

## F15.3: opt-in Web Push (2026-11-04)
- **Strictly opt-in.** Students (profile tab) and parents (bottom of the page) see "알림 받기" only when the console has a VAPID public key and never in the taste build. iOS allows Web Push only for a web app launched from the home screen (16.4+): in Safari the box shows that one line instead of a button. "알림 끄기" unsubscribes in the browser and on the Worker.
- **Keys:** `daybook push keys --subject mailto:…` makes a P-256 key pair with the standard library (checked against the RFC 8291 example key) into daybook.json, refuses to replace existing keys without `--force` (new keys end every subscription), and prints the three `wrangler secret put` commands (VAPID_PRIVATE, VAPID_PUBLIC, VAPID_SUBJECT). Nothing goes into the repo; the demo uses the RFC's published example key pair only.
- **Worker** (v8): D1 `pushsubs` (one row per browser endpoint; at most 5 browsers per link) and `ptokmap` (parent links, so a parent page can opt in; a parent link still cannot upload anything). A link that is retired or rotated loses its subscriptions at the next token-map push; a moved student's follows the new class. `POST /push/send` (teacher) encrypts per RFC 8291 (aes128gcm, a fresh ECDH key and salt per message) and signs a VAPID ES256 JWT (RFC 8292) with WebCrypto only, in `worker/src/webpush.js` (vendored, ~100 lines); no third-party push service, library or CDN. 404/410 from the push service deletes the subscription.
- **Rules (in the Worker):** quiet hours 22:00–08:00 KST (`PUSH_QUIET`) send nothing (the console logs `push_quiet`); at most `PUSH_PER_DAY` (1) push per subscription per day; batches of `PUSH_BATCH` (10, at most 40) per request because of the free plan's subrequest and CPU limits (the console loops while the Worker says "more"). Kinds per subscription: students video / message / report / test, parents report only.
- **Payload:** the title "AMP 학습 기록", a generic text from strings.ko.json (`push_*`; a custom text must pass the same scrubber as student lines: no name, phone or id) and the subscriber's own page URL, encrypted end to end to that browser. The service worker (now also registered for `/p/` when a parent opts in) shows it and opens only same-origin URLs.
- **After 발행** (CLI and Teacher tab; `"push_after_publish": false` turns it off): one student push (새 영상 n개 if videos were added since the previous publish, else 선생님 메시지 if a note was written since, else the weekly update) and the weekly update for parents; the daily cap means nobody gets two. `daybook push send --class … --kind … [--text]`, `daybook push count`, and the Teacher tab's 알림 (counts per role, never who; preview text; send) do the rest. Every send or skip is logged in events.
- **Service worker fix found on the way:** `/static/` is cache-first, and the cache name was fixed (`daybook-shell-v1`), so a phone kept an old app.js after a redeploy. The published sw.js now names its cache after a hash of app.js / app.css / sw.js, so every publish that changes them replaces the cache.
- Tests: the RFC 8291 vector (byte for byte), the VAPID JWT verified with the public key, subscribe validation, a fake push service decrypting each message, quiet hours at 23:30 / 07:59 / 08:00 KST, the daily cap, 410, unsubscribe, retired links; pushes are in the budget test (20 subscriptions, one batched send, the cap).

## F19.1: voice notes from a CLOVA Note transcript (2026-11-04)
- **Input:** iPhone dictation is too weak for Korean, so the teacher records in Naver CLOVA Note and exports text. `voice import <file.txt|-> --class <c>` (preview; `--save` stores) or Teacher tab → 음성 메모 가져오기 (paste or a .txt file; UTF-8, or CP949 from a Windows editor). Speaker labels (참석자 1), timestamps (00:12:31) and line breaks are stripped. Utterances start at the spoken keywords 칭찬 / 개념 / 장면 / 취소 when they stand as words of their own (개념을, 장면이 do not split a line) and run until the next one; 취소 drops the utterance before it (the preview still shows it, struck through). Text before the first keyword (CLOVA's title and date line) is ignored. A shoutout line whose text says "개념" as a separate word is split there; the preview shows it.
- **칭찬 <call sign> [n점] <text>:** `students.callsign` (console only, not in `students_public`): a short spoken name or seat number, unique per class by its spoken form (칠번 = 7번), never a link token, a full name or a student ID (`roster edit <slug> --callsign 7번`, or the roster's 호출명 box). Matching: jamo edit distance ≤ 1, particles read through (가람이, 하늘한테), number words both Sino and native (칠 번, 한 점, 일 점, 열두), and digits must match exactly (7번 is never 1번). One candidate at the best distance = matched (exact, or "비슷하게 들림"); two or more = 누구? with them as chips; none within 1 = 누구? with the 2–3 nearest. 누구? lines are never guessed and never stored by `--save`; in the tab the teacher picks a chip or the select. Points default to 1 (0–5).
- **Nothing is stored before 저장.** Saving re-checks every row on the console side (the browser is not trusted): the student must be active in that class, and a line becomes teacher-only (`shoutouts.private = 1`) when it has a negative word (`filters/shoutout_negative.txt` + a gitignored `.local.txt`: 혼나, 떠들, 늦, 안 했, 못 했, 졸, 장난, 핸드폰 …; spaces ignored), fails the F18 word filter (a Python port, `console/wordfilter.py`, tested against the JS on the same samples) or the PII lint (a full name, a phone, a raw ID). Events: `shoutout` per line, `concept_note`, `moment_draft`, and one `voice_import` summary.
- **Where it shows:** korea mode: the student's own positive lines on their page (나 → "🎤 선생님 한마디", latest 10, re-checked at every publish) and today's list on the board ("오늘의 칭찬", display name + line). manitoba mode: teacher-only (no page, no board). Negative or filtered lines are teacher-only in both modes. 🎤 points are a separate count; they change 태도 only with `"voice_points_to_attitude": true` (added to that day's score, capped at 3). Pages carry no call sign.
- **개념** lines go to the teacher-only "오늘의 개념 메모" list (a later overnight video seed). **장면** lines become text-only drafts; 승인 offers the text on the board's 장면 올리기 box (a suggestion list), ✗ drops it. The demo seeds call signs (새벽 = 4번) and imports `demo/voice/clova_sample.txt` (synthetic) for 콩's class, so the taste build shows 콩's 선생님 한마디.
- The Shortcut endpoint (a direct call from the phone) is later; this is the paste/file path only.

## F19.4: the teacher remote, "tap who, speak what" (2026-11-04)
- Why: iPhone dictation and CLOVA Note both mishear names and nicknames (ms, 아이스), while points come through and math words get garbled. So the name comes from a TAP, never from speech; the praise is typed or said into the phone keyboard's own mic (no Web Speech API, no audio recorded or sent).
- `/t/remote/` on the Worker: a dark, one-hand phone page (installable: manifest, a small service worker for the shell). Today's class is chosen from the class days and start times (a select switches); a "반 전체 👏" button on top; the class as 2-column name buttons ≥ 64 px tall, by seat (a call sign like 7번) then name, with a 🎤 n badge for today's saves; a tap opens a sheet: +1 / +2 / +3 (default +1), a text box, quick chips (daybook.json `"remote_chips"`, default 잘했어 · 풀이 깔끔 · 질문 좋았어 · 발표 최고 · 끝까지 해냄), 저장. A toast at the top offers 취소 for 2 minutes. At most one save per student per 3 s (the phone and the Worker both refuse a second). Offline saves wait on the phone with their own id and time and are sent once (the Worker ignores an id it already has).
- **Names never reach the Worker in the clear.** The console encrypts the class lists (class name, days, start, and per student the link token, the label and the seat) with `remote_key`, a random 32-byte key it writes into daybook.json; the Worker stores only that ciphertext. Encrypt-then-MAC with HMAC-SHA256 only (a keystream from HMAC(k_enc, nonce | counter), a tag over nonce | ciphertext): the standard library on the console, WebCrypto on the phone, no new dependency. The key and the teacher token reach the phone once inside the setup link's #fragment, which browsers never send to a server; the page stores both on the phone and removes the fragment. The Teacher tab's 리모컨 card shows the link as a QR on screen only (it is never printed: it carries the teacher token; `remote link` prints it in the terminal), and 새 키 만들기 rotates the key. The page shell is public and carries no data; every data call needs the teacher token, so a student's or a parent's link token is refused (401).
- Storage: the Worker keeps shout-outs by token (or "*" plus the class key for 반 전체) for 30 days; `daybook pull` (and the board's own poll during class) brings them into the same `shoutouts` table as F19.1 with `source = remote` and the remote's id as `ref`; an undo deletes the row. The F19.1 rules apply unchanged: the F18 filter or the PII lint keep a line teacher-only, a negative word holds it as 확인 필요 (below), korea mode shows a student their own public lines and the board shows today's list, manitoba mode keeps them teacher-only. The board's live state carries 오늘의 칭찬, so a save shows within one poll. Worker v12 (doctor wants it). The remote's few UI labels live in its script (worker/src/remote_client.js), like the Worker's push texts.
- Budget: 40 taps per class (plus the badge refreshes, 3 undos and two page loads) stays far under 30 % (budget test).
- Taste build: `/remote/` with 콩 and 7 invented names (none from the demo roster; the taste lint would refuse them), the same script in its taste mode; nothing is sent.

## F19 addendum: the teacher's own phrasing (2026-11-04)
- **반 전체:** the remote's top button and, in the transcript import, 전체 / 다 같이 / 우리 반 / 모두 as the target make a class shout-out (`class_shouts`): its points go to the class goal through `class_bonus` (source `shout`; an undo removes them), it shows on the board as "반 전체", and it adds nothing to any one student.
- **Natural lines:** besides the 칭찬 keyword, a line that says a call sign as is (particles read through) is a 칭찬 of its own, wherever the name sits ("나이스 가람! 1점 적립 - 지각 안했네", "좋아, 아이스 그걸 맞췄네 1점!", "도담, 잘했어용, 빠르게 해석했네!"); a line with only an explicit points phrase (N점 추가 / 적립, 일단 N점, N점!) is a 칭찬 for 누구?. A natural line never runs on into the next one; a keyword utterance still does (CLOVA wraps lines).
- **Points:** "N점", "N점 적립", "N점 추가", "추가 N점", "일단 N점", "N점!"; spaced forms ("두 점") only with 적립 / 추가 / 일단 or at the end of a clause, so "이 점 잘했어" is not 2 points. When a line has two, the LAST one counts ("2점 줄려했는데, 일단 1점" = 1). Default 1.
- **확인 필요:** a negative word (지각, 늦, 떠들 …) no longer hides a line silently. In the preview the line is marked 확인 필요 with a one-tap 공개 / 비공개; a negated one ("지각 안했네", "안 늦었네", "실수 없었네") starts on 공개, any other on 비공개, and the teacher decides. A remote save with a negative word arrives held (teacher-only) and waits in the Teacher tab's 최근 칭찬 with 공개 / 비공개. The F18 filter and the PII lint stay hard rules, also for a line the teacher made public.
- Casual endings and slang (잘했어용, ㅇㅋ, 아까비, ㅎㅎ, 나이스, 오키) pass the F18 filter unchanged (a test).
